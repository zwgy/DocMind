# 来文运行时调度与文档解析配置实施方案

## 背景与范围

本方案是 `2026-09-07-历史来文错峰批量接入设计.md` 的补充实施项。基础的批次登记、PostgreSQL 调度真相、Redis 短消息投递和来文专用 Worker 已完成；本次只补齐运行时配置、可观测性、知识库复用 Markdown 和管理界面，不改变三类来文入口的业务边界。

## 已确认的设计

1. 管理页改为“来文”和“处理任务”两个页签。“处理任务”保留刷新，新增调度设置入口；下载失败在列表中显示简短原因，并可查看完整错误。
2. 历史任务窗口、来文并发、下载超时和自动重试次数由管理员在运行中修改。配置保存到既有 PostgreSQL/文件配置和 Redis 运行时快照；API、Dispatcher、Worker 最多五秒内刷新。
3. 来文 Worker 保持单实例。ARQ 进程固定安全容量为 4，调度器以可运行时调整的 1 至 4 作为实际准入上限。降低并发不会中断在途任务，只阻止继续投递；提高并发会在下一次调度补位。
4. 历史窗口默认为 `18:00` 至次日 `07:30`，且允许跨午夜。窗口结束后不启动新的历史任务，已经启动的任务自然完成。即时任务全天可投递并优先。
5. OCR 放在“设置 -> 文档解析配置”作为系统默认值。知识库上传的“使用系统默认配置”继承它，显式选择引擎或禁用 OCR 仅覆盖该次上传。来文即时/历史任务无显式覆盖时继承系统默认值，并在首次执行前固化最终解析参数。
6. 来文的“批量入库”只接收分块参数。已存在的受信任 MinIO Markdown 被标记为知识库文件的解析结果，再执行分块、向量化和索引，禁止再次调用 `Parser.aparse` 或 OCR。
7. 任务 `status` 表示调度状态，`stage` 改为中文业务进度：待接收、待下载、解析中、分类与抽取中、已完成、处理失败。失败的机器错误码与完整诊断保留在后端，列表只显示可读摘要。

- [x] Task 8.1：新增运行时配置字段、窗口/并发校验和 Dispatcher 同步。
  - 验收：窗口和并发变更无需重启；无历史任务时只执行低频索引查询；无效窗口或越界并发拒绝保存。
- [x] Task 8.2：让来文解析解析器采用系统默认值或任务快照，并保留知识库单次覆盖语义。

  - 验收：覆盖窗口边界、即时优先、失败恢复、重复批次、Markdown 复用和运行时配置刷新；仅使用隔离样本。

## 风险控制

- 不直接把几千份任务推入 Redis；PostgreSQL 继续作为唯一任务真相。
- 不把原始文件放入 PostgreSQL；MinIO 只受容量约束，需在生产历史批量导入前单独做容量和吞吐验收。
- 不在本次引入 Worker 多副本、抢占或动态改变 ARQ 进程数。MinerU/本地模型无法并行时将运行时并发维持为 1。
- 测试环境不启用 MinerU；线上启用 OCR 前仅需在“文档解析配置”选择引擎并填写该引擎支持的 JSON 参数，受保护的服务地址和协议字段仍由部署配置控制。
