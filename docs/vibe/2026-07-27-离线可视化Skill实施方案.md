# 离线可视化 Skill 实施方案

> 状态：已完成（2026-07-28，代码、单元测试与禁网容器渲染验收通过）
> 日期：2026-07-27
> 最后审核：2026-07-28
> 范围：一期，仅实现数据图表、流程图、思维导图的本地生成与对话内展示

## 1. 最终方案

一期采用“一个可移植能力包 + 一个路由 Skill + 三个执行子 Skill + 三个按需工具 + 两个本地渲染引擎”的结构：

```text
visualization
├── visualization -> 路由，不依赖渲染工具
├── data-chart   -> render_data_chart -> ECharts SSR -> SVG
├── flowchart    -> render_flowchart  -> Graphviz     -> SVG
└── mindmap      -> render_mindmap    -> ECharts tree -> SVG
```

核心约束：

1. 所有 `SKILL.md`、references、工具说明、校验错误和面向用户的提示均使用中文。
2. Skill 目录名、tool 名、JSON 字段名继续使用 ASCII，避免破坏现有注册、函数调用和跨平台路径约束。
3. 主 Skill 只承担能力打包和模糊请求路由，不依赖渲染工具。
4. 三个子 Skill 分别依赖一个专用渲染工具和共享的 `present_artifacts`；模型读取对应子 Skill 后才看到专用渲染工具。`present_artifacts` 未作为基础工具配置时随子 Skill 激活，已作为基础工具配置时保持全程可见。
5. 模型只生成业务数据映射或受限结构，不生成 ECharts Option、DOT、SVG、HTML 或任意 JavaScript。
6. 数据库查询、上传文件等已有完整数据通过沙盒文件传递，系统不得把完整内容二次复制到模型上下文或渲染工具参数。
7. 渲染产物统一为 SVG，默认只向用户展示 SVG。
8. 可视化生成链路禁止 CDN、远程字体、远程图片、远程 GeoJSON、`npx -y` 和在线编辑器。
9. 渲染失败必须返回明确错误，不得生成示例图或切换到不受控格式伪装成功。
10. CSV 使用成熟解析库处理引号、逗号、换行和 BOM；不手写通用 CSV 解析器。

## 2. 目标与非目标

### 2.1 一期目标

- 支持柱状图、折线图、面积图、饼图和散点图。
- 支持包含开始、处理、判断、结束节点的基础流程图。
- 支持水平树和径向树两种静态思维导图。
- 支持中文标题、标签、图例和节点文本。
- 支持从 MySQL 聚合结果、用户提供的小型数据和规范化 CSV 生成图表。
- 生成文件写入当前文件线程 `/home/gem/user-data/outputs/`。
- 使用现有 `present_artifacts` 在对话中显示 artifact 卡片，点击后使用现有图片预览和全屏链路查看 SVG。
- API、worker 和 Agent 沙盒均不需要在运行期访问公网。

### 2.2 一期非目标

- 不实现 Markmap 交互预览。
- 不实现 Mermaid、draw.io、PlantUML、Vega-Lite 或 Plotly。
- 不实现 HTML 图表、动态图表和前端在线编辑器。
- 不新增聊天内自动展开的图表缩略图或专用图表组件；一期沿用 artifact 卡片和文件预览交互。
- 不实现 DOCX/PDF 图片嵌入。
- 不实现地图、桑基图、雷达图、热力图、关系图等扩展图表。
- 不直接读取 XLSX、Parquet 或数据库原始大表。
- 不实现通用 ETL；原始大数据必须在查询或数据准备阶段聚合为 chart-ready CSV。
- 不新增 Skill 隐藏、分组或“仅作为能力包展示”的数据库字段和前端机制。
- 不实现“只保留最后一个 Skill”的单值激活模式；同一次用户请求内允许组合多个 Skill。
- 不修改子智能体禁用 `present_artifacts` 的现有策略；子智能体生成可视化时只返回路径，由主 Agent 完成最终登记。
- 不改造现有远程 Skill 安装功能；内网部署不得依赖它安装本能力包。

## 3. Skill 拓扑与按需加载

### 3.1 目录结构

```text
backend/package/yuxi/agents/skills/buildin/
└── visualization/
    ├── scripts/
    │   ├── package.json
    │   ├── package-lock.json
    │   ├── render_data_chart.mjs
    │   ├── render_flowchart.py
    │   └── render_mindmap.mjs
    └── skills/
        ├── visualization/
        │   └── SKILL.md
        ├── data-chart/
        │   ├── SKILL.md
        │   └── references/
        │       ├── category-series.md
        │       ├── part-to-whole.md
        │       └── correlation.md
        ├── flowchart/
        │   ├── SKILL.md
        │   └── references/
        │       └── modeling.md
        └── mindmap/
            ├── SKILL.md
            └── references/
                └── outline.md
```

外层 `visualization/` 是可整体复制的能力包，`skills/*/` 下四个目录才是注册到 Yuxi 的标准 Skill。这样既能一起维护主 Skill、子 Skill、references、确定性渲染脚本和依赖锁文件，又不会把三个子 Skill 随主 Skill 完整复制到 `/home/gem/skills/visualization/`，避免出现不会触发激活的嵌套 `SKILL.md`。

核心渲染实现不拆到通用 `yuxi.renderers` 包。能力包迁移到其它平台时整体复制外层 `visualization/`，再注册 `skills/*/` 中需要的 Skill。

共享脚本和依赖锁文件不属于任一单独 `BuiltinSkillSpec.source_dir`。修改输入协议、脚本或依赖时，必须同步提升受影响的四个内置 Skill 版本并重建 API/worker 镜像，避免 Skill 文本与实际渲染能力版本错配。

### 3.2 注册关系

在 `backend/package/yuxi/agents/skills/buildin/__init__.py` 中注册：

```text
visualization
  skill_dependencies = [data-chart, flowchart, mindmap]
  tool_dependencies  = []

data-chart
  tool_dependencies  = [render_data_chart, present_artifacts]

flowchart
  tool_dependencies  = [render_flowchart, present_artifacts]

mindmap
  tool_dependencies  = [render_mindmap, present_artifacts]
```

四个 `BuiltinSkillSpec.source_dir` 分别指向 `visualization/skills/visualization`、`data-chart`、`flowchart` 和 `mindmap`。运行时仍同步为 `/home/gem/skills/{slug}/SKILL.md`，因此不修改现有 Skill 读取、激活和依赖闭包协议。

四个 `SKILL.md` 的 frontmatter 使用 ASCII `slug`、中文 `name` 和中文 `description`。触发条件全部写入 `description`，正文不再重复“何时使用”；工具、MCP 和子 Skill 依赖只在 `BuiltinSkillSpec` 注册，不在正文复制依赖表。

Agent 配置规则：

- 面向普通 Agent，默认只选择 `visualization`。
- 只需要单一能力的 Agent 可以直接选择对应子 Skill。
- 已选择 `visualization` 时无需重复选择三个子 Skill。
- 当前数据模型没有隐藏子 Skill 的字段，因此主 Skill 和三个子 Skill 都会出现在 Skill 管理列表；一期通过中文名称标明“可视化能力”和“可视化子技能”，不扩展管理界面。

### 3.3 小模型加载规则

主 Skill 的中文指令必须明确：

- 用户明确要求数据图表时，直接读取 `data-chart/SKILL.md`。
- 用户明确要求流程图时，直接读取 `flowchart/SKILL.md`。
- 用户明确要求思维导图时，直接读取 `mindmap/SKILL.md`。
- 只有“做个图”“可视化一下”等类型不明确的请求才读取主 Skill，并在确定类型后读取一个子 Skill。
- 单类请求只读取一个可视化子 Skill；用户明确同时要求多类产物时才依次读取多个。

上下文预算：

| 内容 | 上限 |
| --- | --- |
| 每个 Skill 元数据 description | 80 个中文字符 |
| 主 Skill 正文 | 40 行，约 600 tokens |
| 每个子 Skill 正文 | 80 行，约 1,200 tokens |
| 每个 reference | 80 行，约 1,000 tokens |
| 单个明确任务读取的 reference | 最多 1 个 |
| 单个子 Skill 激活后的专用工具 | 1 个 |
| 单个子 Skill 激活后的共享交付工具 | 1 个 |

编写要求：

- 使用短句、编号步骤和小型表格。
- 每个 reference 只保留一种数据结构族的规则和 1 个最小示例。
- 不复制 ECharts、Graphviz 或 SVG 文档。
- 不在 Skill 中解释底层渲染实现。
- 不使用“尽量”“视情况”等模糊指令；明确必填字段、禁止项和失败处理。

### 3.4 请求级 Skill 激活与工具 Schema

采用“同一次用户请求内累积，新用户请求开始时重置”的通用语义：

- `readable_skills` 表示当前 Agent 配置允许模型读取的 Skill，作用域为整个会话。主 Skill 的依赖闭包使三个子 Skill 始终可读取。
- `activated_skills` 表示当前逻辑请求中已经通过 `read_file` 读取的 Skill，作用域为一次用户请求。
- 同一次请求的 Agent 循环、连续工具调用和人工审批恢复共享同一激活集合。
- 新的主 Agent 用户消息和新的子智能体任务开始时，先清空上一请求的激活集合。
- 子智能体不继承父 Agent 的激活集合；继续既有子智能体线程属于新的子智能体用户请求，也从空集合开始。

实现使用 LangGraph 标准的 `Overwrite([])` 覆盖 reducer 状态，不新增数据库字段、`scope_id` 或自定义重置哨兵：

- 在 `SkillsMiddleware.before_agent` 返回 `{"activated_skills": Overwrite([])}`，将重置逻辑收敛在 Skill 状态所有者内。
- `before_agent` 只位于 LangChain Agent 图的入口，工具循环从 `before_model/model` 重新进入，不会重复清空。
- 新的主 Agent 请求和新的子智能体请求都会从图入口执行 `before_agent`，无需修改 `BaseAgent` 或 `subagent_task.py`。
- `Command(resume=...)` 从中断节点继续，不重新经过 `START/before_agent`，因此审批恢复保留中断前的激活集合。
- `read_file` 激活仍使用现有 `_activated_skills_reducer` 去重合并，因此同一次请求先读取 Skill A、再读取 Skill B 后得到 `[A, B]`。

禁止把重置放在 `before_model` 或 `awrap_model_call`，这两个位置会在同一次工具循环中重复执行并清掉刚读取的 Skill。

生命周期示例：

```text
用户请求 1
  -> before_agent：activated_skills = Overwrite([])
  -> 读取 Skill A：activated_skills = [A]
  -> 读取 Skill B：activated_skills = [A, B]
  -> tools = base + tools(A) + tools(B)

审批恢复请求 1
  -> Command(resume=...)：不重置
  -> activated_skills 仍为 [A, B]

用户请求 2
  -> before_agent：activated_skills = Overwrite([])
  -> 读取 Skill B：activated_skills = [B]
  -> tools = base + tools(B)
```

工具 Schema 注入规则：

- 模型读取 `/home/gem/skills/{slug}/SKILL.md` 后，从下一次模型调用开始，才把该 Skill 的 `tool_dependencies` 加入 `request.tools`。
- 未激活 Skill 的 gated tools 从 `request.tools` 中移除，但仍预注册在 ToolNode，保证激活后可以执行。
- 基础工具不受 Skill 门控。例如 `present_artifacts` 如果已配置为基础工具，将始终可见。
- Skill 依赖只扩大可读取范围，不自动激活子 Skill，也不自动放出子 Skill 工具。
- 工具 Schema 只通过模型请求的 `tools` 字段发送，不复制到 `system_message` 或 Skill 正文；子 Skill 只写工具名称、使用时机和调用步骤。
- 三个子 Skill 共享 `present_artifacts`。激活一个子 Skill 时模型看到一个专用渲染工具；`present_artifacts` 未作为基础工具配置时同时放出，已作为基础工具配置时沿用已有 Schema。同时激活多个子 Skill 时仍只发送一份 `present_artifacts` Schema。

共享工具按工具名处理：

- 多个 Skill 可以在 `tool_dependencies` 中引用同一个已注册工具。
- 当前请求内只要任意一个已激活 Skill 依赖该工具，它的 Schema 就进入模型请求。
- 多个已激活 Skill 同时依赖该工具时，按工具名去重，只发送一次 Schema。
- 同名工具必须对应同一个全局注册实例和同一份 Schema；禁止为不同 Skill 重复注册同名但实现或参数不同的工具。

该机制只卸载后续请求中的工具 Schema，不删除历史消息。上一请求读取过的 `SKILL.md` 内容仍可能保留在消息历史中，直至现有摘要中间件压缩；本期不为此修改历史消息。

实现难度为低，改动集中在 `SkillsMiddleware.before_agent` 和对应测试，不涉及数据库迁移、HTTP API 或前端。主要风险与控制措施：

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 错把重置放入模型循环 | Skill A 刚激活就被清空 | 只实现 `before_agent`，禁止在 `before_model`、`awrap_model_call` 和工具包装器中重置 |
| 错误重置审批恢复 | 恢复后已激活工具消失 | `Command(resume=...)` 原样传递；使用真实 checkpointer 做中断/恢复端到端测试 |
| 误用普通空列表 | reducer 保留上一请求激活项 | 重置值必须是 `Overwrite([])`，为普通 `[]` 无法清空编写回归测试 |
| 子智能体继承父激活状态 | 子模型看到无关工具 | 子任务继续不复制父 `activated_skills`，且每次新子请求自然经过 `before_agent` |
| 小模型误读了错误子 Skill | 当前请求残留一个无关工具 Schema | 请求内不做回滚，避免状态反复切换；依靠短路由指令和固定用例降低误激活，且可视化专用工具总数上限为 3 |
| 每个新请求需要重新读取 Skill | 增加一次 `read_file` 调用和少量延迟 | 保持 Skill 正文短小；明确请求直接读取目标子 Skill，不先读取主 Skill |
| MCP Skill 被重新激活时重复加载 | 增加连接或发现延迟 | 复用现有 MCP 工具缓存；本期可视化仅使用本地工具，不新增 MCP 风险 |
| 历史 Skill 正文仍在消息中 | 仍占用部分消息上下文 | 接受现有消息与摘要语义；本期只控制工具 Schema，不删除历史 ToolMessage |

- references 必须按本项目的 CSV 路径、字段角色映射、流程 JSON 和 Markdown 大纲协议重新编写，不直接复制 DeerFlow 的参数表。

## 4. 运行时组件

### 4.1 代码目录

```text
backend/package/yuxi/
├── agents/
│   ├── skills/buildin/visualization/
│   │   ├── scripts/...
│   │   └── skills/...
│   └── toolkits/
│       └── visualization/
│           ├── __init__.py
│           └── tools.py
└── services/
    └── visualization_service.py
```

职责：

- `tools.py`：定义三个中文工具说明和 Pydantic 输入模型，只校验函数调用参数形状，注入运行时上下文，调用 service，返回虚拟产物路径。
- `visualization_service.py`：承担 Yuxi 适配，只负责用户与文件线程路径解析、输入文件大小预检、输出文件名、子进程超时、SVG 安全检查和 artifact 虚拟路径。
- `render_data_chart.mjs`：读取受控图表请求和 CSV，校验字段角色，构建关闭动画的 ECharts Option 并通过 `renderToSVGString()` 输出 SVG。
- `render_mindmap.mjs`：解析受限 Markdown 大纲，构建关闭动画的 ECharts tree Option 并输出 SVG。
- `render_flowchart.py`：校验受限流程 JSON，构建 DOT、转义文本并调用本地 `dot` 输出 SVG。
- 图表字段、流程结构和思维导图层级等领域规则只由三个可移植脚本裁决，Yuxi service 不复制第二套领域判断。
- 三个脚本采用统一 CLI：从 stdin 读取一份 JSON 请求，只接受一个 `--output` 临时 SVG 路径，在 stdout 返回一行小型 JSON 摘要。
- service 通过 `stdin=PIPE` 传递请求，不额外落盘请求文件；输入 CSV、流程 JSON 或思维导图大纲仍由路径引用。
- 三个脚本不导入 Yuxi 模块，不访问网络，不直接登记 artifact，也不输出 SVG 正文。
- 成功时退出码为 0，stdout 只能包含一行 JSON 摘要；失败时使用非零退出码，stdout 不得伪造成功结果，stderr 只输出不含宿主路径的简短原因。
- service 必须校验退出码和 stdout JSON；缺失、超量或格式错误都视为渲染失败。
- Skill：只告诉模型何时读取 reference、怎样准备输入、怎样调用工具及怎样交付。

### 4.2 工具注册

新增 `yuxi.agents.toolkits.visualization` 后，在 `yuxi.agents.toolkits.__init__` 中导入该模块，使 `@tool` 在启动时完成注册。

三个工具均使用：

- `category="visualization"`，不进入 Agent 的通用 `buildin` 工具选项；否则工具配置为空时“默认选择全部内置工具”的现有语义会使三个渲染工具绕过 Skill 门控。
- 中文 `display_name`、`description`、字段说明和错误信息。
- Pydantic `args_schema`，所有输入模型设置 `extra="forbid"`，拒绝未声明的 ECharts、DOT 或样式字段。
- 三个工具共用一个小型 `handle_validation_error` 格式化器，把缺失字段、额外字段、类型错误和枚举错误转换为简短中文错误并保留失败状态；最多返回 3 个字段问题，不回显原始调用参数或 Python 异常。
- Skill `tool_dependencies` 门控；不加入 Agent 默认工具列表。
- `ToolRuntime` 获取 `file_thread_id` 和 `uid`；只有 `file_thread_id` 缺失时才使用 `thread_id`。
- 解析、读取和写入都使用同一个文件线程 ID，与现有 `present_artifacts` 保持一致，保证子智能体生成的文件落在父子共享文件空间。
- 三个工具的 `output_name` 均为 1 至 80 个字符的 ASCII 文件名主体，只接受字母、数字、下划线和短横线，不接受扩展名、点或目录分隔符；后端统一补全 `.svg`。数据图表标题限制为 1 至 200 个字符。

`present_artifacts` 作为三个子 Skill 的共享依赖，不重复实现 artifact 登记。主 Agent 激活任意可视化子 Skill 后即可完成“渲染 -> 登记 -> 展示”。现有子智能体后端会过滤 `present_artifacts`；一期不改变该策略，子智能体只返回已生成路径，由主 Agent 负责最终登记。

### 4.3 可移植边界

能力包可复用部分：

- 中文主 Skill 和三个中文子 Skill。
- 按需 references。
- 三个渲染脚本及精确版本的 Node 依赖清单。
- 输入协议、领域校验、图形主题和 SVG 生成。

Yuxi 平台适配部分：

- `@tool` 注册和 Skill 工具门控。
- `ToolRuntime` 身份与线程信息。
- 沙盒虚拟路径解析、跨用户隔离和 outputs 写入。
- `present_artifacts` 登记与前端预览。

迁移到其它 Agent 平台时，应整体复制 `visualization/` 能力包，并为三个稳定输入协议各实现一个薄工具适配器；不得把 Yuxi 的用户、线程或 artifact 逻辑写回能力包脚本。

### 4.4 统一返回协议

三个工具成功时只返回小型结构化结果：

```json
{
  "artifact_path": "/home/gem/user-data/outputs/sales-trend.svg",
  "summary": "已生成折线图，共 12 个数据点、2 个系列"
}
```

约束：

- `artifact_path` 必须是当前文件线程 outputs 下的虚拟路径。
- `summary` 只包含图形类型、数据点和系列/节点数量，不回传完整数据。
- `artifact_type` 固定为 SVG，输入源路径已存在于调用参数，两者不重复返回。
- 同名 SVG 已存在时不得覆盖，按 `name-2.svg`、`name-3.svg` 顺序选择可用名称。发布前使用 `O_CREAT | O_EXCL` 原子占用候选文件名，随后立即用已校验的同目录临时文件原子替换占位文件；任何异常都删除本次占位文件，避免并行工具调用互相覆盖。
- 文件先写入同目录、带随机后缀的临时文件，完成 SVG 校验后再原子发布为最终文件；成功或失败都清理临时文件。
- 失败时返回中文错误，不创建最终 SVG，也不要求模型调用 `present_artifacts`。
- 参数、输入文件或渲染失败时由工具抛出中文 `ToolException`，使工具消息标记为失败并允许模型按错误建议修正；不得用普通成功结果承载错误。

## 5. 数据图表协议

### 5.1 输入数据格式

一期只接受 UTF-8 或 UTF-8 BOM 的标准 CSV：

- `source_path` 必须以 `.csv` 结尾。
- 第一行为唯一列名。
- 分隔符固定为英文逗号。
- 使用锁定版本的 `csv-parse` 解析 RFC 4180 常见形式，正确处理引号内逗号、双引号和换行。
- 空行忽略；列数不一致、引号不闭合、重复或空列名直接报错。
- 最多 50 列，单个列名最多 128 个字符，文件不得包含 NUL 字节。
- 日期字段作为有序文本传递，由数据准备阶段保证顺序。
- 图表所用数值列必须可以解析为有限数值。
- 柱状图、折线图、面积图中的空数值保留为 `null`，表现为缺口；全部为空时报错。
- 饼图数值不允许为空、负数或非有限数值。
- 散点图 `x`、`y` 必须是有限数值；可选 `size` 必须是非负有限数值。

输入文件只允许位于当前用户的：

```text
/home/gem/user-data/workspace/
/home/gem/user-data/uploads/
/home/gem/user-data/outputs/
```

### 5.2 工具参数

`render_data_chart` 使用统一的字段角色映射，不为每种图表暴露完整 ECharts 参数：

```python
class ChartEncoding(BaseModel):
    category: str | None = None
    values: list[str] = Field(default_factory=list)
    series: str | None = None
    name: str | None = None
    value: str | None = None
    x: str | None = None
    y: str | None = None
    label: str | None = None
    size: str | None = None


class RenderDataChartInput(BaseModel):
    source_path: str
    chart_type: Literal["bar", "line", "area", "pie", "scatter"]
    title: str
    encoding: ChartEncoding
    output_name: str
```

不使用 `Union`、递归模型或大型 `oneOf` Schema，降低本地小模型函数调用难度。

### 5.3 字段要求

| 图表类型 | 必填映射 | 可选映射 | 对应 reference |
| --- | --- | --- | --- |
| `bar` | `category + values` | `series` | `category-series.md` |
| `line` | `category + values` | `series` | `category-series.md` |
| `area` | `category + values`，且 `values` 仅 1 项 | 无 | `category-series.md` |
| `pie` | `name + value` | 无 | `part-to-whole.md` |
| `scatter` | `x + y` | `label + series + size` | `correlation.md` |

支持两种分类序列数据：

- 长表：一个指标列加一个系列列，例如 `month,region,sales`。
- 宽表：一个分类列加多个指标列，例如 `month,east_sales,south_sales`。

唯一性规则：

- 长表的 `(category, series)` 组合必须唯一。
- 宽表的 `category` 必须唯一。
- 饼图的 `name` 必须唯一。
- 重复项必须在 SQL 或数据准备阶段显式聚合，渲染器不得静默求和、去重或覆盖。

后端必须拒绝：

- 映射到不存在的列。
- 图表类型所需映射缺失。
- 传入未被当前图表使用的矛盾映射。
- `series` 与多 `values` 同时产生含义不明确的组合。
- 面积图传入 `series` 或多个 `values`；一期面积图固定为单序列，避免默认堆叠或遮挡改变数据含义。
- 饼图分类超过 8 个。
- 单图系列超过 12 个。
- 总数据点超过 2,000 个。
- CSV 超过 10 MB。

数据点计算固定为：

- 长表柱状图、折线图、面积图：有效行数。
- 宽表柱状图、折线图、面积图：有效行数乘 `values` 数量。
- 饼图和散点图：有效行数。

错误返回必须包含：

- 当前图表类型。
- 缺失或错误的映射字段。
- CSV 可用列名和识别出的数值列，最多各返回 50 项。
- 一条可执行的修正建议。

模型只允许根据错误修正一次参数；第二次失败后如实说明失败原因。

### 5.4 数据准备

原始大数据不得直接传给 `render_data_chart`。数据生产方必须生成 chart-ready CSV，并只向模型返回：

```json
{
  "path": "/home/gem/user-data/outputs/.visualization-data/sales.csv",
  "columns": [
    {"name": "month", "type": "string"},
    {"name": "region", "type": "string"},
    {"name": "sales", "type": "number"}
  ],
  "row_count": 12,
  "sample": [
    {"month": "2026-01", "region": "华东", "sales": 1280000}
  ]
}
```

SQL 必须先使用 `GROUP BY`、时间粒度、筛选和必要的 Top N 将数据压缩到可读图表规模。数据库输出和上传 CSV 不得被工具重新读回模型上下文；用户消息中原本包含的小型表格不可避免地已经在上下文中，后续只允许通过一次 `write_file` 调用写入文件，不再传给渲染工具。

不同数据来源的处理规则：

- MySQL：查询脚本直接输出 chart-ready CSV 和结构摘要。
- 用户在消息中提供的不超过 50 行且不超过 32 KB 的小型表格：模型使用 `write_file` 原样写入 `.visualization-data/*.csv`，不得修改、补全或推测缺失值；超过任一限制时要求用户上传 CSV，避免再次复制大段数据。
- 用户上传 CSV：只读取表头和少量样本确认字段，完整文件由渲染工具直接读取。
- 用户上传的非 CSV 表格：一期明确提示暂不直接支持，不通过模型逐行转换大型文件。

## 6. 流程图协议

### 6.1 定义文件

模型使用 `write_file` 将流程结构写入当前文件线程：

```text
/home/gem/user-data/outputs/.visualization-specs/purchase-approval.flow.json
```

文件结构：

```json
{
  "title": "采购审批流程",
  "direction": "TB",
  "nodes": [
    {"id": "start", "label": "提交申请", "kind": "start"},
    {"id": "review", "label": "部门审批", "kind": "process"},
    {"id": "approved", "label": "是否通过", "kind": "decision"},
    {"id": "end", "label": "流程结束", "kind": "end"}
  ],
  "edges": [
    {"source": "start", "target": "review", "label": ""},
    {"source": "review", "target": "approved", "label": ""},
    {"source": "approved", "target": "end", "label": "是"}
  ]
}
```

约束：

- `definition_path` 必须以 `.flow.json` 结尾。
- `direction` 仅支持 `TB`、`LR`。
- `kind` 仅支持 `start`、`process`、`decision`、`end`。
- `id` 必须为 ASCII 字母、数字、下划线或短横线。
- 标题最多 200 个字符，节点和边标签最多 120 个字符，定义文件最大 1 MB。
- 节点最多 100 个，边最多 200 条。
- 必须且只能有一个开始节点，至少有一个结束节点。
- 所有边的起点和终点必须存在。
- 开始节点不得有入边，结束节点不得有出边；所有节点必须能从开始节点到达，并且都能到达至少一个结束节点。
- 判断节点必须有 2 至 4 条出边，出边标签必须非空且在该节点内唯一。
- 非判断节点最多一条出边；重复边和孤立节点报错。流程只允许包含判断节点且存在退出分支的显式回边，拒绝自环和无法退出的闭环。
- 不允许模型提供 DOT、URL、HTML 标签或 Graphviz 属性。

### 6.2 工具参数

```python
class RenderFlowchartInput(BaseModel):
    definition_path: str
    output_name: str
```

工具读取定义文件，映射固定节点形状和项目统一主题，调用本地 `dot -Tsvg`，并将结果写入 outputs。

## 8. 文件与 artifact 数据流

### 8.1 数据图表示例

```text
用户请求
  -> 读取 data-chart/SKILL.md
  -> 必要时读取一个图表 reference
  -> MySQL/数据准备生成 chart-ready CSV
  -> 模型只接收路径、列信息、行数和一条样本
  -> render_data_chart(source_path + chart_type + encoding)
  -> worker 按 file_thread_id 解析路径并读取完整 CSV
  -> ECharts SSR 生成 SVG
  -> 写入 /home/gem/user-data/outputs/result.svg
  -> 工具只返回 SVG 虚拟路径和简短摘要
  -> present_artifacts([result.svg])
  -> 前端按 image/svg+xml 展示
```

### 8.2 模型上下文边界

进入模型上下文：

- 用户请求。
- Skill 元数据。
- 当前子 Skill 正文。
- 至多一个 reference。
- 数据路径、列名、类型、行数和一条样本。
- 用户原本在消息中提供的小型表格，以及模型生成流程定义或思维导图大纲时的一次 `write_file` 参数。
- 当前子 Skill 对应的一个专用渲染工具 Schema。
- 共享的 `present_artifacts` Schema；如果它已是 Agent 基础工具，则沿用同一份，不重复发送。
- 工具返回的产物路径或中文错误摘要。

不进入模型上下文：

- 数据库产出和用户上传 CSV 的完整内容。
- 已写入文件的流程图 JSON 和思维导图大纲的重复副本；渲染调用和结果只传路径。
- ECharts Option。
- DOT。
- SVG 正文。
- Node 和 Graphviz 的完整日志。

### 8.3 产物规则

- 工具始终只生成一个用户可见 SVG。
- 输入 CSV、流程定义和思维导图大纲是数据源，不作为默认交付物展示。
- 中间输入保存在 `.visualization-data` 或 `.visualization-specs` 子目录。
- 将这两个目录加入 `chat_service._write_file_delivery_candidates` 的自动交付排除前缀，避免 `write_file` 成功回执把中间输入误判为最终 artifact。
- 用户明确要求“同时提供源文件”时，`present_artifacts` 才同时登记源文件。
- SVG 文件名使用模型给定的 ASCII 安全主体；后端统一补全 `.svg`，拒绝点、目录分隔符和路径穿越。
- 主 Agent 使用 `present_artifacts` 登记 SVG；子智能体只把路径返回主 Agent，由主 Agent 登记。

## 9. 渲染依赖与离线部署

### 9.1 Node 依赖

MySQL 报表脚本运行在 Agent 沙盒，不在 API/worker 镜像内。为避免现有 PEP 723 `pymysql>=1.1.0` 在首次 `uv run` 时联网解析依赖：

### 9.3 运行期离线

- 可视化生成、MySQL 数据准备和默认启动过程不执行 `npm install`、`npx`、`uv run`、`pip install`、`apt-get` 或远程下载。
- 不读取远程图片、字体、CSS、GeoJSON 或脚本。
- ECharts、Graphviz、中文字体和 PyMySQL 均从对应镜像本地加载。
- 完全隔离部署通过预构建的 API/worker、前端、sandbox-provisioner 和沙盒运行时镜像导入，或通过内网镜像仓库完成。

## 10. 安全与稳定性

### 10.1 路径安全

- 所有输入路径使用现有 `resolve_virtual_path(file_thread_id, path, uid=uid)`。
- 只允许读取当前用户的 workspace、uploads 和当前文件线程 outputs。
- 只允许写入当前文件线程 outputs。
- 所有真实路径解析后再次检查所属根目录。
- 输出文件名只接受安全文件名，不接受绝对路径、目录分隔符、`.`、`..` 或隐藏文件名。

### 10.2 渲染安全

- 不接受 `rawOption`、DOT、HTML、JavaScript formatter 或任意渲染配置。
- 所有标题和标签作为纯文本处理。
- Graphviz 标签集中转义，不拼接用户提供的属性名和值。
- 子进程使用参数数组且 `shell=False`，可执行文件和脚本路径由后端固定，不接受模型传入。
- 先移除 Graphviz 已知的固定 XML/DOCTYPE 前导，再在 XML 解析前拒绝任何剩余的 `<!DOCTYPE` 和 `<!ENTITY`；不处理任意用户 DTD。
- SVG 输出必须以 `<svg` 根元素解析成功。
- 使用 XML 解析器检查 SVG，拒绝 `script`、`foreignObject`、`image` 和事件处理属性。
- `href`、`xlink:href` 及 CSS `url(...)` 只允许 `#id` 内部引用；禁止网络地址、协议相对地址和文件路径。
- 允许 SVG 标准命名空间 URI；命名空间声明不视为网络资源。
- ECharts 和 Graphviz 子进程超时设为 20 秒。
- SVG 最大 5 MB，超过限制视为渲染失败。
- stdin 请求 JSON 最大 64 KB，stdout 和 stderr 分别最多保留 64 KB；stderr 只写截断日志，返回模型的错误经过中文归一化，不返回完整命令或宿主路径。

### 10.3 视觉基线

- 数据图表默认画布 1200×720。
- Graphviz 流程图由 `dot` 计算画布；思维导图按节点和深度扩展画布并设置上限。
- 两个 ECharts 渲染器固定设置 `animation: false`，保证 SSR 输出静态、确定且不依赖浏览器计时。
- 使用透明或白色背景，正文和标签使用高对比中性色。
- 数据系列使用固定的 12 色高区分度调色板；同一图内不得循环复用颜色。
- 字体栈固定为 `Noto Sans CJK SC`、`Microsoft YaHei`、`PingFang SC` 和 `sans-serif`；服务端使用首选字体计算布局，SVG 不嵌入字体文件也不引用远程字体。
- SVG 必须包含 `<title>` 和 `<desc>`，用于辅助技术和文件检查。
- 标签按图形类型执行确定性换行或截断，并在 SVG 对应元素中保留完整文本说明；不允许文本与图形明显重叠。
