# 模型上下文长度自动解析方案

## 背景

Agent 的上下文压缩与请求准入需要确定模型完整上下文窗口。现有模型配置允许 `context_length` 为空；当 LangChain 模型资料也没有 `max_input_tokens` 时，运行时会报“缺少上下文预算配置”，导致管理员切换到新模型后无法提问。

## 目标

- 管理员仍可手动配置模型实例的真实 `context_length`，手工值优先级最高。
- 添加或编辑 Chat 模型且未填写窗口时，尽力从配置的 OpenAI-compatible `/models` 接口获取常见扩展字段。
- 模型服务未返回窗口时，运行时依次使用 LangChain profile 和 32K 默认窗口，避免因元数据缺失直接阻断对话。
- 模型管理页展示当前生效值及其来源，默认值需要明确提示风险。
- 配置阶段的网络探测与聊天运行时解析隔离；聊天、模型切换和 Worker 执行不发起额外探测请求。

## 范围

### 本次实现

- 来源优先级：`manual` → `models_api` → `langchain_profile` → `default`。
- `/models` 常见字段：`max_model_len`、`context_length`、`max_context_length`、`max_input_tokens`、`top_provider.context_length`。
- `default_context_window=32768`。
- UI 自动探测、来源标签、默认值风险提示。
- 历史显式 `context_length` 缺少来源时按 `manual` 处理。

### 暂不实现

- Ollama `/api/ps` 自动探测；开发测试环境由开发人员通过 `ollama ps` 核对后手工配置。
- GPUStack 管理 API、Model Route Meta 或部署后端参数解析。
- 定时刷新、聊天时探测、模糊模型 ID 匹配。

## 行为约束

1. 只有 Chat 模型且 `context_length` 为空时才调用探测接口。
2. 探测只按远端模型 ID 精确匹配；未找到、无有效字段或请求失败时不阻止保存。
3. 探测成功的值保存为 `context_length`，来源保存为 `models_api`；用户修改数值后来源改为 `manual`。
4. LangChain profile 和默认值不写入持久化 `context_length`，由运行时实时解析。
5. API 返回只读的 `effective_context_length` 与 `effective_context_length_source` 供 UI 展示，保存时必须丢弃。
6. 任意已知窗口都必须大于有效输出预留与安全缓冲之和；已发现但不兼容的窗口不得用 32K 掩盖。

## 验收标准

- [x] 手动值覆盖模型服务、LangChain profile 和默认值，并显示“手动配置”。
- [x] vLLM 风格的 `max_model_len` 可被识别、保存并显示“模型服务”。
- [x] 标准 `/models` 不返回窗口时，模型仍可保存和对话。
- [x] LangChain profile 存在时显示“模型资料”并使用其窗口。
- [x] 所有来源均缺失时使用 32768，UI 显示“默认值”及警告。
- [x] 历史模型无来源字段时保持兼容。
- [x] 非 Chat 模型不保留上下文窗口及来源字段。
- [x] 聊天与模型切换不产生 `/models` 探测请求。
- [x] 后端单元测试、接口相关测试、前端 Lint/构建通过。
