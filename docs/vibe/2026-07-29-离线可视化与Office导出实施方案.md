# 离线可视化与 Office 导出实施方案

## 背景

现有离线可视化已经使用 ECharts SSR 生成数据图表，思维导图由 AntV Hierarchy 布局并通过 ECharts SSR 输出，流程图由 Graphviz 生成；旧内置
导出 MCP 能生成基础 DOCX、PDF 和 XLSX，但只能接收模型参数，无法使用当前
用户与文件线程上下文安全读取图表产物，也不支持在 Office 文件中插入图片。

项目尚未上线，本次直接以原生 Tool 和 Service 替换旧 MCP，不保留兼容入口。

## 目标

1. 数据图表继续使用 ECharts SSR，流程图改用 D2，思维导图使用 AntV Hierarchy 双向布局与主题化 ECharts graphic。
2. 可视化统一交付 SVG；只有 Office 导出需要时才临时转换成 PNG。
3. 新增具有 `ToolRuntime` 上下文的原生 Office 导出工具，支持 DOCX、PDF、XLSX 和本地图片。
4. 新增 `office-export` Skill，通过按格式拆分的 references 约束模型输入。
5. 业务 Skill 只通过 Skill 依赖名复用 `office-export` 入口，不感知其安装路径和 reference 文件名；
   通用格式契约由 `office-export` 自己维护。
6. 优化 chat iframe 的静态 SVG 缩略图和完整预览，不引入图形编辑能力。

## 范围与边界

- `export_office_file` 只接收当前会话中的定义文件虚拟路径、输出格式和输出文件名。
- DOCX/PDF 共用文档 block 模型；PDF 继续通过 LibreOffice 将 DOCX 转换为 PDF。
- XLSX 使用 workbook/sheet/rows/images 模型，图片采用单元格锚点。
- 支持 PNG、JPEG、GIF、BMP、TIFF 和 SVG 图片；SVG 使用离线转换器临时生成 PNG。
- 图片真实路径、Base64 和任意外部 URL 不进入模型参数。
- D2 只接收后端从受限 flow JSON 生成的源码，不允许模型直接提交 D2、DOT 或 SVG。
- D2 v0.7.1 只在镜像构建阶段通过可覆盖的 `D2_GO_PROXY` 下载并编译；运行镜像只携带
  固定二进制，不需要 Go 工具链、外网、数据库或额外服务。
- ECharts、csv-parse 和 resvg 的依赖清单由 `backend/package.json` 统一维护，属于后端 Node
  运行时，不归属于任何 Skill；Service 不反向引用 Skill 目录。
- 不实现 Office 模板上传、目录域、页眉页脚、公式编辑、图形交互或拖拽排版。

## 验收标准

1. 原生工具的模型 Schema 不暴露 `runtime`，且拒绝定义文件以外的额外参数。
2. 非当前会话目录、越权路径、错误定义类型和格式不匹配均返回明确中文错误。
3. DOCX 能插入 SVG 派生图片和图题；PDF 能保留相同内容；XLSX 能在指定单元格插入图片。
4. Office 导出成功后只留下目标 Office 文件，不留下临时 PNG。
5. `office-export` 每个 reference 的示例都能通过真实 Pydantic Schema 校验。
6. `build-risk-ledger` 和 `summarize-assessment-actions` 不再依赖旧 MCP。
7. 业务 Skill 不包含 `office-export` 的物理 reference 路径，SVG 转换器不引用可视化 Skill 目录。
8. 全仓不再存在旧内置导出 MCP 及其格式专用工具入口。
9. D2 在无外部资源的容器环境中生成可通过现有安全校验的中文 SVG。
10. 思维导图具有稳定主题、层级配色和可读标签；大型 SVG 缩略图不再被压缩到 240px。
11. 后端单元测试、Ruff、iframe 测试、类型检查、Lint、构建和关键端到端验收通过。
12. DOCX/PDF 中的纵向长图按页面可用宽高等比缩放，不裁剪、不超出页面。
13. DOCX、PDF、XLSX 交付物都能在 iframe 中预览并下载；Office 预览按需转换为 PDF，下载仍返回原文件。
