# 来文证据定位与核心信息抽取方案

## 背景

本地部署模型可能无法稳定逐字复制原文，PDF 解析也可能在句子中插入换行或页码。另一方面，如果把每个章节、条款、款项或执行步骤都转换成结构化 item，结果虽然完整，却会重复全文细节，降低管理页面的可读性，也会增加后续问答读取结构化结果的成本。

结构化结果的定位不是全文的替代品，而是帮助用户快速理解来文主旨、关键结论、重要责任、核心动作、重要时间和主要风险。需要核验细节时，Agent 仍可按附件读取全文。

## 目标

- 只发布有原文依据的核心结构化信息，不穷举正文细节。
- 不设置机械条数上限，避免按模型输出顺序截断重要内容。
- 抽取策略不依赖文档分类、章节命名、标题格式或特定样本内容。
- 证据定位使用简单、可解释的确定性规则，不根据相似度猜测模型意图。
- 样本只用于回归验证，不参与策略选择或生产分支判断。

## 处理规则

### 抽取粒度

1. 全部附件合并后的内容能放入模型输入预算时，整份来文只调用一次抽取，不因分类、标题或章条结构强制拆分。
2. 超出输入预算时，按附件使用现有通用长文本分块。分块只控制模型上下文，不定义结构化 item 的业务边界。
3. 只提取对文档主旨、关键结论、重要责任、核心动作、重要时间或主要风险有直接价值的事项。
4. 同一主题、目标或责任语境下的背景、依据、流程、例外和实施细节合并概括，不把每句话、每一款或每个步骤单独列项。
5. 只有主题、责任对象、目标或时限存在实质差异，且拆分后仍是用户需要关注的关键事项时才拆项。
6. item 中的具体主体、数值、日期、义务和结论必须由同一段连续引用直接支持；无法共同支持时只保留引用能够支撑的核心结论，不拼接分散细节。
7. 不设置结果条数上限。条数由文档中的核心事项决定，而不是由标题数量、篇幅或固定配额决定。
8. 管理页面继续按业务 Schema 分组并默认折叠明细，不引入依赖章节标题的展示契约。

现有知识库分块预设面向检索入库，部分策略会重建或规范化文本。来文抽取在超长时暂用保留原文内容的通用上下文分块，以便 evidence 回到完整附件定位。只有分块器能够稳定返回原文区间和来源元数据后，才适合直接复用更专门的策略。

### 证据定位

1. 先做原文精确匹配。
2. 再做 NFKC、引号、空白和独立 PDF 页码的确定性归一化匹配，并保留原文索引用于回写真实引用。
3. 不使用模糊相似度，也不根据某类公文的文件名、页眉文字或章节样式增加特化规则。
4. 主分类依据无法定位时不发布依据，但保留分类和摘要；附加分类依据无法定位时不进入额外抽取路由。
5. 结构化条目依据无法定位时不进入正式结果，只记录日志、告警和 `dropped_item_count`，不保存完整未核验候选。
6. 模型调用、JSON/schema 解析或分块失败会阻止整份结果发布，避免把部分抽取伪装成成功。

确定性定位证明的是“引用文本确实存在于原文”，不能在不引入语义模型的情况下证明“概括字段完全由引用蕴含”。提示词要求 item 中的具体事实都由引用直接支持，但本地模型仍可能偶尔生成范围略宽的概括。当前不增加二次模型审核或样本化语义规则；需要核验时由 evidence 回看全文，无法逐字定位的候选则不发布。

## 数据兼容

- 管理要求涉及多个部门或岗位时允许保存字符串数组，避免拆项或丢失责任对象。
- 模型用 `null` 表示原文未说明周期时，按业务语义规范为“未明确”；其他非法周期值仍校验失败。
- 超长文本的来源位置使用“正文第 N 部分”等用户可理解的标签，不暴露内部 chunk ID。

## 真实来文回归

使用 `inc_939aa647c5201f2d` 的三份已有 Markdown 和当前默认模型 `deepseek:deepseek-v4-flash` 连续执行两次抽取，分别发布 9 项和 6 项核心管理要求，远少于旧章节/条款策略的 105 项。两次模型及 Schema 错误均为 0；第一次无引用丢弃，第二次有 1 个候选因引用无法逐字定位而丢弃。

结果覆盖使用单位职责、运行限制、人员上岗资格、检修约束、安全协议和报废条件等核心内容，没有再按章、条、款枚举。两次条数存在波动，说明本地模型输出具有随机性，因此条数只作为观察数据，不作为生产分支、固定配额或验收阈值。回归中发现过一次摘要合并范围大于单段引用的问题，已增加通用提示约束；不据此增加面向该文件内容的代码规则。
