# 历史来文批量接入简化实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 `/api/incoming-documents/ingest-batches` 简化为无批次实体、支持 1 至 200 份历史来文的文档级幂等登记接口，并同步修复输入校验、失败重传、URL 来源限制和上传脚本。

**Architecture:** PostgreSQL 的 `incoming_ingest_jobs` 继续作为唯一任务事实来源，以 `(source_system, source_document_id)` 保证幂等。HTTP 层完整校验请求后，仓储按稳定身份顺序登记或复用任务；Dispatcher 和 Worker 仅依据任务优先级、状态、令牌和历史时间窗口执行。

**Tech Stack:** Python 3.12、FastAPI、Pydantic v2、SQLAlchemy async、PostgreSQL、ARQ/Redis、pytest、requests。

**Spec:** `docs/vibe/2026-09-08-历史来文批量接入简化设计.md`

## Global Constraints

- 保留 `POST /api/incoming-documents/ingest-batches` 路径，删除 `batch_key`、`name` 和所有批次生命周期接口。
- 项目处于开发阶段，不实现旧接口兼容或旧数据迁移。
- 单请求 1 至 200 份来文且编码后不超过 5 MiB；远程来源只做适合受控内网的基础 URL 校验。
- 先写失败测试，再实现最小代码；后端测试放在 `backend/test`。
- 不降低已有即时任务优先级，不删除令牌、租约和 Worker 时间窗口复查。
