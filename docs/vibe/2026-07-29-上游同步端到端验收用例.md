# 上游同步端到端验收用例

## 1. 目标与边界

本轮验收针对 `docs/vibe/2026-07-28-上游Yuxi增量同步方案.md` 中已同步、部分同步或明确保留 DocMind 实现的高风险运行链路。目标不是重复执行所有单元测试，而是确认部署环境中的真实服务、浏览器界面、SSE 和持久化状态能够连通。

以下内容不作为本轮通过条件：上游未移植且已明确记录原因的审批/Steer 生命周期、全局 OCR、异步子智能体重构、models.dev 目录、HTML 预览和依赖大版本升级。它们不是本次同步产物，混入验收会产生错误结论。

验收环境：`docmind-dev` 的 `/mnt/docMind-dev-v1.0`，分支 `feature/docMind-dev-v1.0`。

## 2. 前置条件

- API、worker、web、chat-iframe、PostgreSQL、Redis 和 MinIO 均为运行状态。
- 使用专用验收会话；除测试产生的会话/消息外，不修改业务配置、知识库或远端源代码。
- 涉及模型回答的断言只验证可观察协议与约定短语，不以模型长文具体措辞作为通过条件。

## 5. 结论规则

- 每项标为“通过、失败、阻塞或不适用”；“不适用”必须写明与同步边界的对应关系。
- 浏览器路径失败时，先保留服务端日志、run/request 状态和 API 响应，再判断是界面、SSE、worker 或模型问题。
- 若 QUE-01/QUE-02 因模型生成过快无法稳定制造排队窗口，则该项改用已覆盖持久化状态迁移的 API/服务测试，不把“未观察到窗口”误报为功能失败。
