# 历史来文错峰批量接入实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 为三类来文入口提供 PostgreSQL 驱动、可恢复、错峰执行的接入任务系统，并在既有来文管理中提供必要运维能力。

**Architecture:** PostgreSQL 保存批次、成员和接入任务真相；独立 ARQ 来文 Worker 只消费有执行令牌的少量任务；来文 Dispatcher 在数据库租约下选择一个可执行任务。现有 `incoming_documents`、附件、业务抽取和候选表继续保存业务产物，任务完成时通过同一事务发布有效抽取运行和来文状态。

**Tech Stack:** FastAPI、SQLAlchemy async/PostgreSQL、ARQ 0.28、Redis、MinIO、Vue 3、Ant Design Vue、pytest、pnpm。

**Spec:** `docs/vibe/2026-09-07-历史来文错峰批量接入设计.md`

## Global Constraints

- 历史任务只在 `Asia/Shanghai` 的 18:00（含）至次日 07:30（不含）启动；Worker 启动前再次判断。
- 首版只启动一个 `incoming-worker`，`max_jobs=1`；来文内下载、解析、摘要调用串行。
- PostgreSQL 是任务状态事实来源；Redis 只保存带 `job_id + delivery_token` 的短队列消息。
- 所有业务发布必须检查输入版本、执行令牌和租约；允许至少一次外部调用，不允许旧执行覆盖有效结果。
- 历史原件只在夜间从上游长期有效接口下载；即时 JSON/multipart 保持现有同步接收契约。
- 测试默认 `INCOMING_OCR_ENGINE=disable`；线上 MinerU 配置另行验证后启用。
- 不增加 Worker 多副本、抢占、Redis 队列编辑、复杂报表或浏览器批量导入器。
