## 验收中修正

首轮补充集成测试为 50 通过、2 失败。原因是 `ensure_live_api_schema` 使用 `anyio.run` 建表后没有关闭 PostgreSQL 连接池，后续用例复用了属于已关闭事件循环的连接资源。修正仅在该夹具内增加 `try/finally`：在事件循环退出前关闭连接并复位初始化标志。使用同一修正文件只读挂载复验，最终 52 项通过；没有修改产品运行逻辑。

本记录及夹具修正随后通过 Git 同步到 `main` 和功能分支；只涉及测试和文档，无需再次重启已验收的应用。

最近运行日志中的 ERROR 已核对为测试触发的 4xx 输入校验、资源不存在和权限拒绝；其中通知首次请求的 UTC offset 与上海时区不一致被正确拒绝，使用一致时区后创建和投递成功。API 和调度/Worker 最终检查未发现非预期运行异常。

### 当前生产条件与剩余边界

- 当前远程仍是现有开发 Compose 部署，目标目录没有 `.env.prod`。本次只验证生产 Compose 结构，不把临时占位配置当作真实生产配置或启动验收。
- 主机实测：内存约 220 GiB，检查时可用约 130 GiB；系统盘 438 GiB，剩余约 34 GiB、使用率 92%；RTX 4090 显存 24564 MiB，已使用 23979 MiB。内置 CPU OCR 无需新增 GPU 服务；正式部署前需结合独立目录、镜像和数据增长需求确认磁盘余量。
- RapidOCR 首次识别实际下载约 21 MB 的三个 ONNX 模型，保存在 API 容器的 `site-packages/rapidocr/models`。当前实例可正常识别；重建容器后可能再次下载，隔离网络的生产镜像应提前准备模型并验证冷启动，不能仅凭本次联网验收推断离线可用。
- 本次测试证明指定样本的识别、入库和检索结果正确，尚未验收复杂版面/表格、手写或低质量扫描件、真实业务长文档的问答质量、并发容量和图检索。删除测试知识库时出现既有的图向量库连接回退告警；本轮普通文档向量/全文检索通过，不据此宣称图功能通过。
