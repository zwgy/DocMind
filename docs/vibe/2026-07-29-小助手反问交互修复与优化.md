# 小助手反问交互修复与优化

日期：2026-07-29

## 目标

修复 `chat-iframe` 中 `ask_user_question` 的协议与展示问题，优化反问卡片在普通悬浮窗口中的视觉和操作体验，并在部署到 `docmind-dev` 后完成真实端到端验收。

## 需求范围

1. 完整支持 `allow_other`：
   - 有预设选项时展示“其他”选项。
   - 选择“其他”后显示自定义答案输入框。
   - 单选和多选均按既有协议返回 `{ type: "other", text, selected }`。
2. 隐藏内部恢复消息：
   - 提交答案后不展示原始 JSON 用户消息。
   - 拒绝回答后不展示内部 `reject` 用户消息。
   - 实时完成和刷新历史后的表现一致。
3. 优化反问卡片：
   - 使用替代聊天输入区的底部操作面板，与历史消息形成清晰层级。
   - 通过四周留白、完整边框、分层背景和轻量阴影形成独立操作面，避免与聊天背景混为一体。
   - 顶部不使用装饰图标，标题与提示居中展示。
   - 标题、问题和选项使用清晰且紧凑的字号层级，常见双问题表单在默认窗口中可直接完整展示。
   - 选项具备明确的 hover、focus、selected 和 disabled 状态。
   - 底部按钮等宽对称、间距统一，次操作与主操作层级明确。
   - 新问题或刷新恢复中断后，问题区域从第一题开始展示。
4. 修复普通悬浮窗口横向溢出：
   - 执行过程、工具列表和反问卡片不扩大消息区域宽度。
   - 460px 默认窗口中不出现非必要的水平滚动条。
5. 检查浏览器错误：
   - 确认项目源码是否产生 `MutationObserver` 报错。
   - 若报错来自浏览器注入环境且无项目来源，不增加无依据的运行时回退。
6. 修复历史会话定位：
   - 用户选择已有会话并加载完历史后，立即定位到最后一条消息。
   - 页面刷新后首次展开处于隐藏状态的小助手，窗口恢复尺寸后立即定位到最后一条消息。
   - 历史定位不使用平滑动画，流式回答继续使用平滑自动滚动。

## 验收标准

- [ ] `allow_other=true` 时可输入并提交自定义答案。
- [ ] 单选、多选和混合“其他答案”的恢复载荷符合工具契约。
- [ ] 提交与拒绝产生的内部恢复消息不在聊天记录中展示，刷新后也不展示。
- [ ] 未完整回答时主按钮禁用，完成全部问题后启用。
- [ ] 中断期间刷新页面后问题卡片可恢复。
- [ ] “暂不回答”可恢复任务并让 Agent 明确停止当前任务。
- [ ] 反问面板替代聊天输入区，并以完整边框、分层背景和轻量阴影与聊天记录清晰区分。
- [ ] 标题居中，标题、问题和选项字号层级清晰，操作按钮等宽对称。
- [ ] 默认悬浮窗口中的常见双问题表单可直接完整展示，长表单仅问题区域滚动。
- [ ] 新问题或刷新恢复中断后，问题区域从第一题开始展示。
- [ ] 选择已有会话后，聊天记录立即定位到最后一条消息。
- [ ] 页面刷新后首次展开已有长会话，聊天记录立即定位到最后一条消息。
- [ ] 默认 460px 悬浮窗口不存在消息区横向溢出。
- [ ] 相关前端测试、类型检查、Lint 和构建通过。
- [ ] 代码推送后，`docmind-dev` 远端 HEAD 与本机一致，相关容器健康。
- [ ] 部署后的 Codex 内置浏览器端到端验收通过。
