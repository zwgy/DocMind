# 离线分包与代码挂载实施计划

> 执行方式：使用 superpowers:executing-plans 逐项实施，最后独立审查。

**目标：** 首次交付分开的镜像包，后续普通代码更新只传应用包，不重复传运行环境。

**已确认需求：** 用户选择拆包和代码挂载，明确暂不精简或更换沙盒、后台依赖；内网部署保持简单高效。沿用现有 Docker Compose、镜像、配置与数据路径，不增加镜像仓库、差分平台或自动回滚系统。

**方案：** 基础服务包包含 PostgreSQL、Redis、Neo4j、Milvus、etcd、MinIO；应用环境包包含 API、Web、iframe 三类镜像；沙盒包包含运行沙盒和管理服务。应用包包含后端源码、沙盒管理服务源码、构建后的两套前端、Nginx 配置及现有部署工具。各应用容器只读挂载对应目录，数据库和其他业务数据保持原位置。

**运行方式：** 首次将三个镜像包和应用包放入部署目录，解开应用包后 init、install。后续联网侧从 Git 提交生成代码包，复用首次交付的环境清单；内网执行 `bash deploy.sh update /path/docmind-app-新版本.tar.gz`。更新前校验文件与环境标识，停止九个应用服务，整体替换 app 目录以清除已删除源码，重新创建应用服务；不重启基础数据库、不导入镜像、不覆盖本机配置。依赖或运行镜像构建输入变化时明确要求重新交付镜像，不尝试兼容。

**边界：** 前端源码必须先在构建侧生成静态文件；内网不安装 Python/Node。运行环境镜像保留现有内容，挂载覆盖其中代码；本次不优化镜像内部体积。保留基础校验和环境一致性检查，不增加复杂版本管理。
